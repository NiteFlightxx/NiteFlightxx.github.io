# 知识库文档维护流程

## 组织原则

知识库采用直接阅读的文档形式，不是课程平台。内容按理解所需的先后关系排列，但不添加学习目标、练习验收、完成打卡或空白规划课节。

每个概念只保留一份完整解释。其他文章保留理解当前上下文必需的符号、公式与短摘要，再链接主文。不为了缩短篇幅删除独特的源码证据、推导或交互。

## 文件与 URL

正文放在 `src/content/knowledge/<slug>.md`，规范 URL 为 `/knowledge/<slug>/`。已公开文件名不随标题修改；改变标题时，把旧标题放入 aliases，保留检索能力。

`/knowledge/` 直接显示入口文档；`/knowledge/library/` 提供搜索、筛选、收藏和最近阅读。旧课程和领域地址只是兼容别名，不新增介绍页。

`src/data/reading-order.json` 是侧栏和上一篇/下一篇的顺序来源。每篇公开文章恰好出现一次；没有正文的主题不进入目录。`prerequisites` 表示真正必要的概念依赖，不能把“可能相关”都写成先修要求，也不能形成循环。

当前入口为“动力学总览”，共同基础为总览、质点的状态与守恒、连续介质；之后平行展开刚体、可变形体和流体，再通过多物理耦合连接。数值积分、约束、理论表述和源码是各分支的共享工具，不能将完整刚体引擎设成软体/流体的统一前置要求。先建立物理模型，再区分空间离散、时间离散与数值求解。主文需交代概念的依赖及其解决的问题，避免只有相同标题模板。

每个目录 section 必须声明 `mode: sequence` 或 `mode: reference`。只有前者显示序号和同一 section 内的上一篇/下一篇；后者按需查阅，不跨节强行串联。主线的 frontmatter 依赖、后续文章与导航保持一致；可选工具放在 related 或正文上下文链接中。

关键空间、因果和流程关系应配图，不把整篇内容替换成图，也不只在卡片中重复正文。物理几何用可核对的 SVG，结构和流程可用已经正确渲染的关系图；交互通过现有 DemoMount 按需接入。图需有中文标签、图注、可访问名称，标明示意与比例，验证主题、窄屏文字与箭头。配图 skill 调研见 `docs/diagram-skills-research-2026-10-24.md`。

## 标题与摘要

标题使用明确的主题与范围，例如“数值积分：方法、误差与稳定性”。不再强制“详解 — 从……到……”句式，不使用“终极、统一框架、全掌握”等无法兑现的表述。

- 标题原则上不超过 48 字符，保留 UE、GJK、XPBD 等可检索术语。
- 摘要用一句话说明独特内容，不枚举全文所有章节。
- 开头直接说明问题、模型或范围，可补必要的站内链接。
- 不再使用“学习位置、前置积木、本文模块”等全库重复模板。
- 章节标题直接命名概念，不写“第一块积木、顺水推舟”等引导话术。
- 内容顺序自然展开，不强制所有文章套相同章节结构。

## Frontmatter

从 `src/content/knowledge/_template.md` 复制，完整填写后再将 draft 改为 false。

~~~yaml
title: "技术主题：明确范围"
excerpt: "一句话说明问题和本文采用的解释方式。"
date: "2026-10-21"
category: "Physics"
subtopic: "ConstraintSolver"
tags: ["约束", "数值方法", "刚体"]
readTime: "阅读约15分钟"
draft: false
kind: "algorithm"
level: "intermediate"
pageType: "guide"
aliases: []
prerequisites: []
nextArticles: []
related: []
sources:
  - title: "实际阅读的一手资料"
    url: "https://example.com/primary-source"
~~~

category 与 subtopic 必须使用 `src/content/config.ts` 与 `src/lib/taxonomy.ts` 中的配对枚举。tags 为 3–6 项。date 采用 ISO 日期，readTime 是估算，不表示完整运行验证耗时。

kind 可用 theory、source、algorithm、comparison、practice、experiment；level 为 foundation、intermediate、advanced。它们用于检索与范围判断，不用于考试或完成度。

源码文章优先设为 pageType: source-analysis，注明快照、文件、函数与行号。不要为了补来源面板加入没读过或并不能支持结论的链接。

## 正文、公式与代码

正文不再写 H1，从 H2 开始，层级不跳级；文章标题由布局渲染，目录自动从正文标题生成。不要手写第二份目录。H2–H6 不写编号，页面与右侧目录按层级自动编号；引用章节使用具体标题和深链接，避免“§4.1”随插章失效。

所有数学统一使用 LaTeX：行内 `$...$`；块级 `$$` 独占行，前后留空行。公式不能放进普通代码块来冒充排版；单位、向量、矩阵和符号首次出现时就地说明。

代码区分可运行示例、伪代码与真实源码。积分阶段、矩阵空间、法线方向、单位与容差必须一致。出现稳定性或精度结论时，写清模型、步长、光滑性与求解收敛条件。

独立示例若用于数值对比，优先让审计直接执行文中的代码，不再复制一套“测试专用算法”。不能据此宣称真实引擎场景或 GPU 性能已经验证。

## 源码与资料

明确分开：

- 源码事实：来自指定版本的文件和直接调用链。
- 一般原理：数学推导或论文模型，不代表引擎已经采用。
- 工程建议：有假设的配置方向，需要场景测试。
- 待验证：运行性能、网络行为、资产接入或证据不足的推断。

项目专题定义仍位于 `src/content/topics/`。通过 topics 的 id、stage、role、order 关联文章，不复制完整正文。领域描述文件在 `src/content/knowledgeDomains/`，不是第二套完整文章。

## 修改已有内容

改写前先检查入站链接、标题锚点、交互挂载与源码出处。删除重复展开时，要留下准确摘要和目标链接；改章名时更新站内深链接，必要时保留旧锚点到新对应章节。

标题修改不更新文件名。不要把发布日期全部改成当天；版本核对日期可以在源码范围段单独记录。旧历史方案不反向约束当前标题和 UI。

静态构建与数学示例通过不等于 UE 运行时或 WebGL 性能测试通过；交付时分别报告。

## 三类正文的职责

本文件是当前写作规则的唯一入口，`course-authoring.md` 仅说明产品方向；旧大纲和历史规划不提供另一套正文规范。复用已有 kind 与 pageType，不增加一套平行分类。

- 原理与算法：kind 采用 theory 或 algorithm，pageType 通常为 guide。维护模型、符号、推导、算法、算例和成立条件；具体项目只作接口说明。
- 源码与实现：kind 为 source，pageType 为 source-analysis。维护指定快照的入口、调用链、状态所有权、阶段依赖与代码证据；通用推导链接主文。参数参考可以保持按任务查询的结构，不必硬套执行流水线。
- 工程实践与参考：kind 采用 practice 等已有值，pageType 按实际内容选择 guide、project 或 interactive。先给输入、操作、参数含义和适用范围，再给示例与失败处理；原理和源码通过链接复用。

同一文章可以包含其他类型的必要摘要，但必须有一个主要职责。源码事实、一般原理和个人设计建议分段表达，不把“如果重写”混入当前实现描述。

## 讲解顺序与深度

采用共同叙述顺序：问题与范围 → 模型与约定 → 核心推导或执行过程 → 示例 → 条件与限制 → 来源及延伸阅读。这是内容顺序，不是七个强制标题。短文合并章节，长篇参考按读者查询任务分组；不要在全库复制相同导言和总结。

同篇比较多个算法时，统一回答：求解对象与假设、更新公式、状态读写、执行顺序、收敛与停止条件、时间/存储/同步代价、同一算例。只介绍直觉的部分明确为概览，不用同样的标题暗示已经具备完整推导或实现。

已有基础不从头重教。原文的独特导数、接口、参数条件和源码证据有保留价值；压缩重复内容后应保留必要局部定义与准确主文链接，不用一条“详见其他文章”替代当前段落所需的解释。

## 术语与技术结论

- 中文首次出现时给可检索的英文术语，随后保持统一。Jacobi 是迭代方法，Jacobian 是导数矩阵，不混用。
- 时间步 n、步内迭代 k、输入与求解候选状态分别定义；固定步、子步、迭代和渲染帧不得互作同义词。
- 有效逆质量 W = J M⁻¹ Jᵀ 与其逆区分；力、冲量、位置层乘子的单位和生命周期分别定义。
- 先定义目标与符号再推导，不在同一推导中混用 A = D+L+U 与 A = D−L−U。
- 对收敛、稳定性、精度、复杂度和守恒量写出模型、离散与求解条件。禁止没有依据的固定加速倍数、毫秒表和引擎优劣排名。
- 论文结果标明版本、图表与实验范围；源码版本固定不等于产品运行验收；保留旧源码记录不自动表示本轮重新验证。

## 示例与证据的维护

代码围栏必须标语言；流程图、目录树和伪代码使用 text。明确哪些片段是源码摘录、局部示意和可运行示例，不把缺失宿主、容量或同步处理的片段当作交付实现。

数值比较先确定一份参数和解析结果，公式、表格、图、代码共用它。文中的可运行示例使用 `knowledge-…-example` 标记，`audit-document-examples.mjs` 直接提取发布代码验证，不再维护另一份同名算法。检查残差、守恒或已知解等行为，而不只比较代码自身生成的快照。

不要求每个 UI 调整或伪代码都新增测试。对关键数值算例、停止条件与退化情况执行适当检查；失败不能通过删除相应断言或把未验证改成通过来解决。

## 章节迁移与验收

自动编号不进入 canonical fragment。既有章节改名或正文重写时，在 `src/data/knowledge-legacy-anchors.json` 将旧 id 指向语义对应的新标题 id，渲染时在目标章节处生成兼容锚点。不要一律指向文章开头。

迁移记录区分全文重写、局部修订和保留内容的格式整理；不能把“34 篇通过格式检查”写成“34 篇技术结论全部重验”。每批核对 URL、正文深链、旧锚点、交互挂载、中文检索和窄屏溢出。

`audit:document-style` 检查格式与元数据一致性，`audit:document-examples` 检查指定算例，`audit:article-html` 检查构建后锚点与公式。它们不替代人工推导、外部源码核对、UE 构建或运行时测试。
